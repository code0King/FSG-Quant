## Context

当前 `pdf_parser.py` 使用 PyMuPDF 的 `page.get_text()` 提取纯文本，在处理中文排版时经常出现文字错乱、顺序颠倒的问题。导致：
- MD&A 章节提取不完整（固定截取 5000 字符，常截断在中间）
- 高管任职表格完全无法解析（表格数据散落在多个文本块中）
- 审计意见、质押比例等只能靠关键词正则，准确率低

需要引入专业 PDF 提取工具，分层提取不同内容。

## Goals / Non-Goals

**Goals:**
- MD&A 文本提取质量达到可用的章节级别（准确识别章节起止）
- 核心人员变动率从 PDF 董监高表格精确提取（计算`终止日期在本年人数/总人数`）
- 提取流程可配置、可缓存、可降级
- 向后兼容：现有接口签名不变

**Non-Goals:**
- PDF 中财务三张报表的精确提取（当前无此需求）
- 图片/扫描版 PDF 文字识别（OCR 不在范围内）

## Decisions

| 决策 | 选择 | 备选 | 理由 |
|------|------|------|------|
| MD&A 提取工具 | PDF-Extract-Kit（纯文本模式） | PyMuPDF / pdfplumber | 版面还原质量最高，对多栏混排支持好 |
| 高管表格提取 | Camelot（lattice 模式） | Tabula / PDF-Extract-Kit 表格模式 | 有线表格提取准确率高，安装轻量 |
| 提取流程架构 | 分层 Pipeline：先提取章节定位，再按需解析 | 单次全量解析 | 避免每次重复解析大 PDF，支持增量更新 |
| 缓存策略 | 中间结果写入 Parquet | SQLite / JSON | 与项目现有存储格式一致 |

## Risks / Trade-offs

- **PDF-Extract-Kit 安装复杂** → 含模型权重（~2GB），需额外磁盘空间和首次下载时间。设为可选依赖，缺失时回退到 PyMuPDF
- **Camelot 依赖 Ghostscript** → 需系统安装 Ghostscript。设为可选依赖，缺失时跳过表格解析，人员变动率保持 0.0
- **解析速度** → 完整解析一份年报约 30-60 秒（含模型加载）。通过缓存中间结果缓解
